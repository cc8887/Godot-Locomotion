## 判断与原规划归属

目标仍是可稳定运行、可人工验证的完整 Godot ALS 示例。当前不能称为已经
1:1 移植：相同动画与部分公式已经存在，但实际 Demo 尚未完整连接动画图的
更新、采样、曲线、缓存、状态历史和最终消费链。修复要补这条链，而不能只
增加延迟、角度限制、手臂偏移或强制脚锁来掩盖外观问题。

最初桌面方案中 Overlay 全系统不在首个里程碑内；用户随后明确要求全部
Overlay 和道具，仓库详细设计已经将其纳入 P5B。本次遵循扩展后的设计，
不以最初版本的排除项缩小范围。音频仍按用户要求暂缓。

## 实施顺序

1. 补全主移动图的剩余依赖。完成 Falling Lean 专属网格、Fall/父级 Jump 的
   独立混合输入和预测落地内容，保留各自的初始化、相关性、来源时间及曲线
   写入。空中与地面 Lean 使用不同网格和附加基准，不能复用配置。
2. 统一 Main Movement 的更新与提交。让 Standing/Crouching/Jump/Fall/Land
   使用同一角色候选状态、来源批次、缓存遍历、Slot/Montage 和最终惯性化。
   替换测试中受控的 Grounded 缓存/父状态；最终图的姿势、曲线、时钟、通知
   一起提交，失败一起回滚。完成后明确标记实际 Demo 入口，不只报告组件测试。
3. 闭合曲线反馈与消费者。区分动画自带曲线、图内 ModifyCurve、混合后曲线
   和下一次更新读取的历史。先接最终 YawOffset 到角色旋转，再接动态上身
   Layering/Add/LS、Aim/Lean、脊柱/手部 IK 和完整脚部/pelvis 约束。
   不能把“缺失”无条件视为“存在且为零”，也不能假定所有动画的曲线 ID 相同。
4. 完成当前视觉问题的整链验收。基础移动、上身和脚部的问题属于 P3/P4
   修复，不推迟到 Mantle/Ragdoll 之后。同步完成所需 P5A 前置能力。
5. 再按 P5A 其余通用动作、P5B Overlay、P5C Mantle/Roll、P6 物理恢复/Camera
   顺序继续，最后执行 P7。已有键鼠体验作为回归基准。

## 当前问题的可检查标准

- 交错步/换髋：在不同起始脚相位输入 A→D、D→A，记录 Feet_Crossing、
  HipOrientation_Bias、源/目标状态权重、允许转换帧、ChangeDirection 权重
  和逐骨骼 BlendProfile。原版等待是条件门控和过渡曲线共同产生的效果，
  不能实现成统一的输入等待秒数。现有 Standing 回放有等待帧，不等于完整
  角色视觉已达到原版。
- 起步滑步：记录实际角色速度、Weight_Gait、Stride、播放倍率、源片段秒数、
  同步 marker、骨骼与角色/平台变换；只在确实接触/支撑的窗口测量脚的相对
  水平位移。此前“低位脚位移”只是诊断代理，不能单独当支撑脚锁定真值。
- 上身/手臂：同一输入下检查最后输出的分层/加法/局部空间权重、骨骼空间
  及 Overlay 掩码；在固定相机横移和自由观察时分别采样胸、髋、上臂/前臂。
  不能以角色直立、画面非空或单帧旋转未超阈值代替动作验收。
- 帧率/多线程：30/60/120 Hz；1/10 角色 single/parallel；状态中断、失去
  相关性后重入，以及姿势/事件晚期失败后同帧重试。
- 对照基准：当前资产来自 ALS V4，以该资产所用 AnimBP 和实际 UE 节点语义
  为直接对照；ALS-Refactored C++ 是算法与架构参考。两版规则差异必须记录，
  不把改名或混用两版公式视为等价。

每项分别记录“正式数据齐全 / 组件运行 / Demo 接入 / UE 对照 / 人工通过”。
代码行数、测试数量和短场景 digest 保持，均不能代替最后三项。
