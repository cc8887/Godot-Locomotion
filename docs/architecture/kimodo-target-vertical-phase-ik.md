# 目标步态：竖直极值相位 → 有界 IK → 严格门禁

目标空间的脚底接触误差不再阻止相位识别。`publish.prepare_target_raw` 在原版时间域重采样后调用 `target_phase.infer_phases`，以竖直曲线识别候选支撑窗口，再由 `target_cleanup.repair_periodic_gait` 修复脚部接触，最后执行既有目标几何与 ALS 曲线协议门禁。源作者检查及回执哈希仍是进入目标转换的前提。

## 相位识别

输入是源作者阶段已截取的一条完整周期，使用目标骨架 FK 和原绑定姿态定义的脚跟、脚掌几何。每只脚的信号为 `h(t) = (heel.z + ball.z) / 2`。忽略重复末帧，以周期 Fourier 的前三个谐波平滑曲线；整段竖直平移不会改变结果。不使用绝对地面高度、FootPlanted 或既有接触标签来推断相位。

在三倍拼接的周期曲线上寻找显著峰、谷，取中间周期，避免循环边界截断极值。峰显著度至少为振幅的 20% 或 0.25 cm；若第二个峰/谷的显著度达到主极值的 60%，视为多周期或歧义。每侧竖直振幅至少 1 cm；左右谷底相隔半周期，允许候选识别误差 ±0.15 周期。

围绕各谷底取 `h <= h_min + 0.1 * (h_max-h_min)` 的连续周期低位区间。将两侧区间变为相对各自谷底的帧偏移，再取共同可靠区间，避免两侧低位平台宽度不同导致推断的落脚时刻错位。共同窗口至少 0.06 秒。保留原测量区间及最终窗口，重复末帧继承首帧候选接触。

这里的低位窗口是 **IK 候选支撑**，不代表已接地、真实受力或最终门禁通过。该算法不从任意长动作自动估计周期，也不把静止脚判定为可修复步态。当前仅启用检查器已支持、原版协议为 `flat_sole` 的周期身份；加速动作、踮脚协议和缺少原版对应的身份不套用这条策略。

## 接触修复与失败边界

IK 在目标空间恢复原版协议定义的行进速度及方向，以候选窗口内脚跟世界坐标的中位数作为固定地面锚点。脚部参考绑定姿态确定平脚方向，保留观察到的水平朝向；脚掌趋向原绑定局部姿态。窗口外侧使用两帧平滑过渡，跨首尾支撑作为同一段处理。

固定骨长的双骨 IK 修改腿部旋转，必要时允许骨盆下移；不延长骨骼。脚踝修正上限 8 cm，骨盆下移上限 5 cm，水平不可达立即失败。上身与 Root 轨道不由接触 IK 重写。循环末端脚部姿态与首帧相同。修复完成后才执行 Root/Pelvis 分解、辅助 IK 重建、逐资产曲线与最终 FBX。

后置严格门禁保持原阈值，检查穿透、足底高度、支撑持续性、滑移、左右接触事件、半周期关系、原版停止帧及 FootPlanted 协议。候选相位允许的 ±0.15 不替换后置事件门禁的 ±0.1。修复超限或相位歧义会保存失败并保留未修复输入，之后仍执行严格门禁。相位识别是修复工具，不作为新的资产质量硬门禁；原输入确实合格时允许不修复，原输入未通过严格质量检查时正式发布仍拒绝。不得把未应用修复的回执写成成功。

原版平脚周期的基线中，前进/侧向 Walk、前进/侧前 Run 与前进/侧前 Crouch 能提供上述交替谷底；两条原版蹲姿后侧移的高度波形不能按这条假设识别。因此不能宣称所有周期动作都由同一种竖直极值规则完整定义支撑。

## 可追溯制品

每个启用身份保存 `target-phase/<source-sha256>/before.raw.json`、`after.raw.json`、`phase.json` 与 `repair.json`。相位回执包含原始/平滑竖直曲线、峰谷帧、原测量窗口及最终候选接触；修复回执包含速度、方向和实际最大修正。文件进入包的载荷哈希，目标门禁报告同时引用相位与修复结果。修复成功仍不替代最终蒙皮滑移或上身视觉验收。
