# 原生物理时间步长与平台阶段边界

在 . 统一 Godot 物理主机的输入步长后，普通 120 Hz 休眠恢复通过，完整矩阵从 **8/12 提升到 9/12**。原生世界的精确轨迹仍未完全复刻，普通角色尚未接入 Core 刚体后端。

## 修正

UE world reference 使用 `const float Dt=1.f/Hz` 调用 Scene.SetUpForFrame，随后 double evolution 使用这个已存储的秒数。Godot callback 则给出 double 的 1/Hz。120 Hz 的两值分别为 0.008333333767950535 与 0.008333333333333333；即使差值很小，持续接触的积分和约束求解也会逐步放大差别。

- 新增 AlsPhysicsStepTime.FromEngineSeconds：在引擎/世界入口转换为 float 秒数，再提升至 double；拒绝无法保存或无法进行 float 倒数运算的输入。
- AlsCoreJointHost 的无外力、有重力、有显式 force、scene 四个入口共用该边界，纯 Core 求解 API 仍按调用方明确提供的 dt 执行。
- StepScene 统一拥有场景 Capture、Island.Step、代理发布和 CommitCapture；kinematic velocity 与本步积分、Gather、迭代、投影、睡眠使用同一秒数。求解失败不提交 scene capture。
- 回放驱动中的平台动画也使用相同步长。首次矩阵发现绝对时间 `(_frame+1)*dt-10` 在第 599/1199 帧提前产生极小正值，导致平台在静止阶段最后一帧唤醒已睡眠角色。现从阶段起始帧计算 `(_frame-hz*10+1)*dt`，六项平台重新验证；保留首次失败日志，没有降低睡眠或唤醒断言。

两份已有独立 UE 世界参考覆盖 30/60/120 Hz，新 Import 检查全部 dtUsed 精确一致且重复转换不改变值。当前普通 120 Hz 的 74 个采样全部 sameStepDuration=true（上一批全部 false），不是修改 golden 来消除差异。

普通 120 Hz：AnimMan 第 679 步、Mannequin 第 1054 步睡眠；两者保持超过一秒，末秒最大线速度/角速度均为零。最大锚点误差 0.5033156104315784 cm，累计接触点 89899。独立进程复跑的完整报告字节一致，SHA256 1D6CC762A2390269CE92857541DF225FC722C567541EA81567635F5A0E4EBD3B。此前同场景 Mannequin 到 1200 步仍醒。

独立原生普通 120 Hz 参考为 AnimMan 第 635 步、Mannequin 第 1004 步睡眠；当前恢复预算通过，不等于休眠时刻或轨迹逐值一致。

普通 30 Hz 当前 AnimMan 第 142 步睡眠，Mannequin 到 300 步仍醒；末秒最大速度 7.0284037590026855 cm/s、角速度 0.39961546659469604 rad/s。既有原生 30 Hz 自身也是 Mannequin 未睡（末秒约 6.98827 cm/s / 0.40352 rad/s），AnimMan 第 159 步睡眠。两种平台 30 Hz 的原生预静止参考也未达到预算。因此三项失败继续保留，同时必须区分原生固有表现和移植差异，不能凭这三个红项单独断定公式错误。

60/120 Hz 平台恢复后均完整经历静止、启动唤醒、随动、停止、再次休眠。120 Hz 平移在 1716/1719 步再次休眠，旋转在 1722/1816 步再次休眠；60 Hz 平移 860/874、旋转 869/1023。首次提前一帧唤醒失败由阶段计时修正解决。
