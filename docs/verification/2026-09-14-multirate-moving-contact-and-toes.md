# 多帧率移动接触与脚趾锚定（第 203 批）

## 本批结果及规划归属

继续 P3/P4 的移动、换髋、停止和完整接触验收。第 202 批已是实际实现
进展；本批将单一 60 Hz 场景扩展成真实 30/60/120 Hz、walk/run、三种
换向时机的 18 组渲染矩阵，并修复矩阵暴露的满锁脚趾变形穿地。

最终 18 组全部通过，15,120 帧、2,160 张 PNG；每脚 780 个实际足部
蒙皮点，最大穿地 0.000835 mm 以内。相同输入的 Cycle、SourceSync、
Standing、Movement 逐字段保持。原生数学等价与该显式几何策略继续分开，
没有切换默认 Demo，也不据此关闭整个 P4、滑步人工验收或后续 P5A–P7。

## 真实物理频率与输入相位覆盖

`P4MovementVisualSmoke` 新增 `--hz=30|60|120` 和
`--reversal-delay=0|0.15|0.3`。每帧断言 Engine.PhysicsTicksPerSecond
及真实 Motor DeltaTime，主线程移动与 Worker 动画均按实际频率运行。
动作时序按物理时长保持：1 秒起步，原 4/7 秒换向加指定延迟，10 秒
停止，总长 12 秒；不是改变报告标签或仅重复/抽取 60 Hz 帧。

换向偏移只改变实际左右输入到达时刻，不修改源动画时钟。汇总器检查
两个换向输入都出现，且每种频率/步态的三组首次换向相位两两环形间隔
大于 0.05，避免重复同一相位。脚相位等待仍由运行时条件产生，不增加
固定 gameplay 输入延迟。旋转诊断按原 60 Hz 每步 30°换算为相同的
1800°/秒门槛；报告保留实际每步角度和角速度。

默认 60 Hz/零延迟输入的重放与第 202 批时序保持。分析器同时支持旧
720 帧捕获和新 capture.json 元数据，逐帧核对实际输入及时间步长。
新脚本 `run-movement-contact-matrix.ps1` 不覆盖已有目录，保存运行和
分析日志；诊断模式保留完整坏帧，旋转违规仍失败。

## 发现的真实缺口

初始 18 组中 17 组通过，120 Hz/run/零延迟失败：停止右脚在 14 个
可见帧超过 5 mm，最差第 1254 帧 −5.223021 mm。此前 60 Hz 的同类
残留为约 −4.257 mm，不能以其未越线认定完整接触已无问题。

连续检查显示脚踝位置、旋转都已固定，但 ball_r 随停止动画继续转动。
新增 `analyze_locked_toe_deformation.mjs` 读取实际绑定和原捕获，重建
第 1221 帧初次满锁到第 1254 帧的 34 帧蒙皮。真实最低点 id=1374
由 ball_r 100% 驱动。仅将 ball_r 局部姿势保留为初次校准值，其他
骨骼和组件变换保持，最低高度从 −0.522290 cm 变为接近零。
计算与实际 Godot 蒙皮最大误差 0.000029024 cm。

这证明本例是最终接触只固定脚踝、未固定鞋底内部变形的问题，而非
应该每帧移动锁定脚踝。证据为 `movement-203-toe-deformation.json`。
没有将这个反事实计算说成重新运行了原 UE 整角色。

## 修复行为

新增显式 `--foot-contact-toes` / PinContactToes，依赖最终接触策略；
要求实际支持几何以及直接 foot_l/ball_l、foot_r/ball_r 绑定，缺失即
拒绝，不静默忽略。设置默认关闭，旧 Refactored/旧接触入口仍可复查。

初次最终锚点建立后，从实际 Rig 输出保存脚趾相对脚踝的局部姿势。
锚点可复用时，按原锁量把当前脚趾局部姿势混合到保存值；满锁保持，
部分释放平滑回到动画，失去支撑、换 collider、关闭 IK、源重捕获或
约束导致锚点失效时一起释放/重捕获。没有改脚踝目标或换髋规则。

脚趾约束在同一 Rig 候选内、腿求解之后和实际几何测量之前执行。
几何多次求解仍从同一已提交历史和原始姿势开始，脚趾约束每次一致；
保存的脚趾历史与原接触锚点一起 Commit/Cancel。Left/RightToePinned
单独输出，避免把运行了普通 IK 误记为真实脚趾接触。

- 原策略矩阵：`artifacts/movement-203-baseline-matrix.json`，明确一组失败。

- 双模式事务：`artifacts/movement-203-dispatch-{single,parallel}.log`。
- 旧平台保持：`artifacts/movement-203-platform-baseline-comparison.json`。
- 新平台三频：`artifacts/movement-203-toe-platform-matrix.json`。

初始六次步行分析曾因 JavaScript strictEqual 区分 IEEE −0/+0 而中止，
实际输入为负单位向量的 Y=−0。已修正为数值零比较，原始捕获不变，
六次重分析通过；原失败日志保留。真实 120 Hz 跑步几何失败仍独立保留，
没有用这个分析器问题掩盖它。最终矩阵所有运行/分析退出 0。

按单频复现，使用新 Prefix 防止覆盖：

```powershell
./scripts/run-movement-contact-matrix.ps1 -Hz 120 -GodotExecutable '<Godot console exe absolute path>' -Prefix movement-check -PinToes
```
