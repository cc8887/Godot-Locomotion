# 足部历史接入 Rest 动态补步

基线 `main / c47390c`，直接在统一主目录实施，用户 README、场景、漫游角色、HUD 和 LayerBlending 修改保留。

## 实现与时序

原来 Demo 的 Rest 输入将左右足锁量、目标和锁点全部填零。原动态选择器、四条动画和共享 Transition 队列虽然已实现，真实角色无法通过这条入口产生补步请求。

按本地 ALS `AlsAnimationInstance.cpp` 的 `RefreshFeetOnGameThread`、`RefreshFeet`、`RefreshDynamicTransitions` 顺序接入：

| 数据 | 生产者及时间 | 消费者 |
| --- | --- | --- |
| IK 脚目标、骨盆 | 上一成功提交的最终姿态；本帧更新前读取 | 本帧足锁更新 |
| 世界目标 | 上一最终局部目标 × 本帧组件变换，UE 世界轴／厘米 | 本帧 Rest 距离判断 |
| 世界锁点、锁量 | 本帧 global 足锁更新，含平台、约束和释放 | 本帧 Rest 距离判断；脚部 Rig |
| AllowTransitions | 上一成功提交的最终输出曲线 | 本帧 Rest 门控 |
| 动态补步请求 | 原 Idle 图回调，保持 8 cm×scale 严格门槛、左右择优和两帧间隔 | 同一角色 Transition 队列，在 PostUpdate 接受 |
| 新目标与曲线 | 本帧最终姿态完成后捕获 | 成功提交后供下一帧读取；取消全部丢弃 |

新增纯值 `AlsFootTransitionFeedback`，带当前帧与最终姿态历史身份。足部 owner 只在 global 阶段允许读取，防止最终输出捕获覆盖候选目标后误读；Rest 拒绝异角色、异代、缺失／过期历史、非有限数、重复或迟到更新。层级宿主在足锁 global 更新后、原 Locomotion 图遍历前传入，未额外求值姿态或调用 Godot 对象。

诊断记录仅在整帧提交时发布：足部反馈、门控、累计反馈帧数和动态请求数。没有新增独立播放器；原四条补步动画仍使用共享角色 bank／queue 和外层 Transition Slot。
