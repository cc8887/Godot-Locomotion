# 实际世界关节输入与首轮求解

本批在主目录 main 继续对齐物理后端。独立 UE 世界观测确认：前三步 114 个关节的图内顺序、228 个质心连接端及有效设置均与 Core 捕获一致；首步用 Core 输入驱动的原生容器，其最终 40 个身体的 V/W 与真实 UE 世界 PostSolve 逐值相同。剩余差异已经缩小到首个有效关节 `pelvis → spine_01` 的求解/缓存计算，尚未证明全部 Gather 中间量相同。

修正线性关节中 .NET 9 `Vector3.Cross` 的舍入差异，显式保留参考引擎分开的 float 乘法、减法。普通 120 Hz 的 Mannequin 现在第 1138 帧休眠，但到第 1200 帧只保持约半秒，没有满足持续一秒的原门槛；矩阵仍为 **8/12**。普通 demo 未接此后端，Ragdoll 稳定性并未完成。

## 实现与独立证据

- 世界导出新增 PreSolve 的实际 joint settings、actor/COM frames、graph order/level/color/sleeping，以及 PostSolve 身体状态。均为只读，回调在退出时清除。与上批全程比较，48040 个身体样本的初态、姿态、速度和 awake 状态未改变。
- `Compare-WorldJointInputs.ps1` 保留原始字段差异：每帧 AnimMan 39 项、Mannequin 37 项，全部为未使用轴的 limit 数值。UE `FPBDJointSettings::Sanitize()` 将非 Limited 轴的 limit 清零；测试仅对此规则归一化后比较全部字段，未改生产设置或忽略其它差异。
- 新增 `-PhysicsCoupledJointTrace`，仅在独立容器重放的首轮使用公开的 range overload，每个关节后记录状态。Gather、迭代数和 projection 不变。6 例的全部 144 个标准阶段与不开跟踪的输出逐字节一致，额外得到 114 个逐关节快照；旧导出调用默认不启用。
- 新测试独立重建 actor→COM 转换，验证输入顺序/设置；首步原生重放与世界输出的 40 个身体 V/W 精确相等，证明这一步可以用同输入重放定位内核。后续步已继承轨迹差异，不做相同结论。
- 参考引擎 `UnrealMathSSE.h::VectorCross` 在当前 Windows 构建使用分离乘减。Core 线性约束的 Gather、位置和速度阶段现采用同样顺序。未改关节参数、休眠阈值或迭代预算。

## 数值结果与限制

6 例×24 阶段的新鲜 Core 重放，.NET 9 修正前/后最大误差：DP 从 `1.092017321e-8` 降为 `9.834166370e-9` cm，DQ 从 `1.210638256e-9` 降为 `1.066964073e-9`，V 从 `7.733918210e-6` 降为 `7.709738384e-6` cm/s，W 从 `4.742691146e-7` 降为 `3.555262253e-7` rad/s。修正后的 .NET 8/9 这四个最大值一致；projection 后位置还有微小运行时差异，不能称全内核跨运行时逐位相同。新参考断言 DP≤1e-8、W≤4e-7，历史捕获保留原值，仅对新鲜重放应用这两个界限。

首轮第一条全自由 pelvis 连接输出相同；下一条 spine_01 就有 DP 残差：AnimMan `2.328306437e-10` cm，Mannequin `1.041250308e-9` cm，DQ 为 0。直接 dot 求和、矩阵轴公式的诊断试验未改变这些结果，未保留这两项生产改动。下一次应针对首个关节 Gather 的实际质量/惯量张量、缓存行和位移累加边界继续独立核对，避免重复检查已一致的资产帧/图顺序。
