# 静态地面接触及释放生命周期（第 202 批）

## 规划归属与本批结果

继续原 P4 Foot IK / Foot Lock / pelvis 接触，以及 P3 起步/停止依赖。
静态地面最终接触锚点已经接入显式完整脚部入口，补齐满锁、释放、失去
支撑、换碰撞体和取消重试。步行/跑步最终各 720 帧、120 张实际渲染截图，
每脚 780 个足部蒙皮点，均通过原 5 mm 穿地门槛。

跑步停止仍有最大 4.257277 mm 负高度，不能称为零穿地。单一 60 Hz
横移场景通过不等于起步滑步、完整 P4、原版整角色或 P7 已验收。
完整入口和几何策略仍显式选择；没有切换默认 Demo、提交或清理用户修改。

## 从移植完整性看后续修复

原方案中的 C++ 是行为和算法参考，资产实际来自 ALS V4。当前实现中，
V4 图语义、Refactored 脚链及 Godot 接触适配应分开标注，不能把混用版本
说成整角色完全照搬。第 201 批原生同输入脚链也复现穿地，因此本批属于
显式接触改进；该结果不能反过来当作原生脚链数值等价的证据。

接下来按既定依赖推进：

1. P3/P4：不同脚相位、30/60/120 Hz、移动/停止/平台、上身和手脚完整
   组合回归；区分脚骨锚点保持、鞋底接触与支撑窗口水平滑移。完成整链
   和人工验证后再切默认完整入口，保持现有键鼠操作基准。
2. P5A：剩余通用 Notify/Notify State 消费、Sync、ActionPlayer/Slot 与
   玩法分发；已有运行时组件不直接等于全部动作已可玩。
3. P5B：13 种 Overlay 的装备、切换、收起、道具挂点和动作组合。完整
   Overlay 已经由用户扩入原详细规划，音频仍暂缓。
4. P5C：Mantle/Roll/Root Motion 的检测、碰撞、平台、中断与运动消费。
5. P6：Ragdoll/Get-up/Pose Recovery、动画与物理所有权切换、完整 Camera。
6. P7：10 个全质量角色的 Release 热身与连续十分钟预算，以及人工签收。

## 代码行为

`AlsFootContactAnchor.SurfaceIdentity` 独立保存真实碰撞体身份。
移动基座仍按 BaseLock 和基座局部空间保存；静态地面继续保持原 ALS 的
BaseIdentity=0，改用 WorldLock.Position 识别源锚点，在世界空间保存
最终脚部位置。静态分支不读取不存在的 PlatformTransform。

当前完整 IK、有效脚和实际地面射线均匹配后才允许接触。初次满锁沿用
现有实际网格几何校准；持续满锁复用锚点，不逐帧抬高或重新捕获。
支持碰撞体替换、静态/相对基座切换、teleport、源位置重捕获、Thigh
约束失效、重新满锁及释放。候选锚点与原锁/Rig/最终姿势一起提交。

首轮静态接入解决跑步停止门槛失败，但步行起步第 71 帧在锁量
0.08333341 时恶化到 6.149158 mm。该回归产物保留，未隐藏失败。
最终把既有 `--foot-ground-clearance` 的消穿地范围扩到已开始释放的
部分锁量：先求原权重下的接触混合位置，再仅沿命中面法线处理负距离。
满锁不进入该修正，释放权重、水平混合位置及保存的锚点不被重写。
同一历史/查询最多三次求解，弹簧与时钟仅推进一次。
