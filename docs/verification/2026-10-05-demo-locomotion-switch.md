# 同一 Demo 的 ALS／Lyra 主控切换

默认入口仍为 `scenes/demo/als_demo.tscn`。F6 或顶部按钮请求切换，`--locomotion=als|lyra` 决定初始模式。P4 世界、移动平台、鼠标视角及相机节点持续存在；独立 Lyra 场景和原 Release Smoke／Terrain 路径继续用于原有回归。

切换宿主在 ALS Observe 之后执行，检查 Worker 已结束、发布与提交身份一致、姿态展示完成。ALS→Lyra 先构造隐藏角色、导入脚底位置／朝向／速度／蹲伏并提交首个姿态，再停用 ALS；这一物理帧不再积分目标移动。Lyra→ALS 用共享只读定义和独立通知上下文创建新角色槽，首个真实姿态提交后释放旧 Lyra。旧 ALS 的输入、碰撞和发布停止；换回时重建动画／平台历史，隔离旧生命周期回调。Overlay、旋转模式、相机模式及装备各自保留，相机输出在 0.18 秒内过渡。两套图的动画相位重新初始化，不承诺动作姿态完全连续。

翻滚、Mantle、Ragdoll／起身和 Lyra Montage 库存未退出时记录请求。自动测试覆盖真实 Emote 的等待与退出；Mantle／Ragdoll 期间的切换没有新增专项矩阵，仅保留现有保护及相机恢复回归。目标准备失败保留当前主控；测试使用确定性的准备故障注入，不代表所有资源损坏和提交后故障均可恢复。

## 验证

Godot 4.7.2 .NET，目标 net8.0／C# 12，构建使用 SDK 10.0.300、Optimize=true，最终 0 错误／0 警告。隔离 worktree 复用当前主目录的 generated 资产，资源原始 JSON／FBX／TRES 字节未重写。用户已有的场景与 UE 导出脚本／测试修改不纳入本批。

| 验证 | 结果 |
| --- | --- |
| 默认入口、ALS／Lyra 两个初始模式，各 30／60／120Hz | 六项通过；每项主测试 11 秒，8 次交接、2 次空中、2 次蹲伏，含 F6 实际物理按键 |
| 60Hz 两个初始模式、九个 Lyra NPC | 两项通过；切回 ALS 后 NPC 继续更新，同一世界／平台身份不变 |
| 交接状态与所有权 | 脚底与速度交接误差均为 0；相机 yaw／pitch 不变，装备恢复，停用 ALS 不再发布帧 |
| 故障与动作 | 每项一次准备失败保持 ALS；真实 Emote 活动期间保留请求，结束后切回 |
| 实际 OpenGL 渲染 | 60Hz 一项通过，九张截图；抽查 ALS、Rifle、Unarmed 及返回 ALS 的四张，HUD 与单角色展示可见 |
| ALS 动作回归 | 240 帧通过；R/X 物理键、替换／取消／完成和主线程回调保持 |
| 原相机故障恢复 | 52 帧、两次容量故障／10 次失败恢复通过；两条预期注入警告 |

报告和截图保存于被忽略的 `artifacts/demo-switch/`，可通过 `scripts/verify-demo-switch.ps1` 重跑。早期编译成员名／命名空间错误、Montage 工作态查询误用的失败记录已保留；改用 committed 库存后全部切换测试通过。新切换运行及普通动作回归没有 Godot 错误或警告。

本批没有修改、启动或导出 UE，没有打包／全量 .NET 回归／十分钟性能或完整人工玩法验收。切换只发布到 main 的合入提交，现有 `v0.2.0-lyra` 的 tag 与 Release 不包含此新功能。
