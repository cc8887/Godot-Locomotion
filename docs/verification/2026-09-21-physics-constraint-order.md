# 接触图分层与约束求解顺序

本批直接在 `.` / `main` 推进 Core 物理移植完整性。
**原生排序规则已完成对照并接入完整链诊断；完整物理稳定性仍未通过。**
平台从此前仅 120 Hz 两项通过，变为 60/120 Hz 四项通过，但实际场景的 30/120 Hz 落地休眠出现回归。
普通 demo 尚未接此物理后端，不能将本批称为普通 Ragdoll 完成，也不能继续引用前批十二项落地全过作为当前状态。

## 缺失的原生行为

此前 `AlsJointIsland` 始终按 PhysicsAsset 数组顺序解关节。
本地 UE 5.9 的 `Chaos/Private/Chaos/Island/IslandManager.cpp` 中，
`AssignIslandLevels` 从零质量支撑端开始广度优先遍历，再由 `SortIslandEdges` 按层级和持续的加入次序排列各容器。
`IslandGroup.cpp` 将该顺序传给容器求解器；相同优先级下碰撞容器仍先于关节容器。
仅有独立接触行、关节行的公式一致，不足以保证整链共同迭代一致。

## 原生对照

新增只读导出入口 `PhysicsGraphOutput=<新的绝对路径>`。
调用原生 `FPBDIslandManager`，以两个 joint container 表示接触、关节两类图边；不运行物理求解，不伪造预期层级。
16 组包含单条悬空边、单条支撑边、无支撑分叉、单/双支撑、同一身体多个支撑约束、闭环及反向加入次序。
导出每个身体层级、边层级、原生容器顺序和加入 key。

`assets/config/v4_physics_graph_reference.json`：19,059 字节。
两次独立冷启动导出退出 0，均输出 `ALS_PHYSICS_GRAPH_OK cases=16 assets_saved=0`，字节一致。
SHA256：`EAE05CA81681014BB63E9720187705FE49837388B96426CAFF1AAE7DF4C380EC`。
首轮 Core 对照发现未连入图的身体应为 -1，而非 0；按原生结果修正，16 组身体层级、边层级和次序全部一致。
单边连通分量保留原生 level 0；多个边共享零质量端不等于合并动态连通分量。
此参考只证明图快照规则，不包含原生整链接触检测、动态拓扑全过程或完整运动轨迹。

## 实现

- `AlsConstraintOrder`：预分配图快照计算、动态连通分量、支撑遍历和稳定排序；输入非法时保留此前结果。
- `AlsContactConstraintOrder`：固定身体/形状拓扑的排序 owner。持续接触沿用加入 key，形状 revision/body generation 改变或接触重新出现取得新 key；边移除采用 swap removal。
  将接触边、关节边一起用于层级计算，分别生成容器求解次序。前一步次序、key 和身份仅随成功 `Commit` 发布；失败可重试。
- `IAlsIslandContacts.PrepareConstraintOrder`：Gather 后、迭代前交接排序。未提供排序的旧 provider 保留既有行为。
- `AlsJointIsland`：位置、速度和投影阶段使用同一关节次序，仍先缓存全部投影行再执行投影。
- `AlsWorldContacts`：可选绑定确定的 island，拒绝跨 island 使用、未准备排序直接求解/提交；排序与接触历史一起提交/回滚。
  `PhysicsCoreJointReplay` 的完整链落地路径已绑定，不按频率或测试成败选择旧顺序。

Core 六项新增语义检查覆盖独立分量、非法输入保持、零分配、支撑改变/消失、错误 owner、缺少准备、失败后身体与历史不变且可重试。
本批没有修改休眠阈值、等待长度、迭代次数或接触/关节行公式。
本图仍服务于预组装身体组，不是完整岛发现、跨岛合并/分裂或局部休眠系统。

| 旋转 | 30 | 失败，未到运动阶段 | A168，M 未睡 | — | — |
