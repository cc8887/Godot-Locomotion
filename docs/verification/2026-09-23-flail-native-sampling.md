# 实际 Flail 采样到原生电机目标的独立对照

新增 `RagdollFrameSmoke --native-motor-reference`，使用生产 `AlsRagdollAnimationSource` 读取真实资源，在原生导出的时间点执行实际采样→逻辑FBX转native→motor target，而不是直接把原生局部姿态喂给目标算法。两套模型各五个时刻，严格核对时长、骨骼名字/父索引，并统计全部局部姿态和180个有效驱动目标。

冻结参考沿用上一批 UE 真实 UpdateRBJointMotors 输出，SHA256仍为 `C5E087DFBCB2929A61FB355582F9AE8945BAE66570DD9DE4302E9574B2CF8320`，未修改参考。

## 结果

日志目录 `artifacts/flail-native-sampling-20260923/`。最终 Optimize 构建零警告/错误，Godot headless 对照退出0：

- 样本10，目标180。
- 骨骼局部位置最大欧氏误差 `1.1952194108132638e-5 cm`。
- 局部旋转最大四元数分量差 `1.1147949974255056e-7`。
- 实际驱动目标最大四元数分量差 `9.117479457532163e-8`。
- 按四元数符号对齐比较，未归一化结果掩盖误差；非有限值拒绝。最终门槛位置2e-5cm、局部旋转/目标2e-7，较初版旋转1e-5门槛收紧，最终独立复跑通过。日志 `sampling-final.log`。

这一结果排除了已采样时刻的大幅轴向或骨骼绑定错误；不等于任意时刻或完整物理轨迹等价，也不能证明微小输入误差不会经接触放大。原生局部姿态直接计算目标的3.33e-16误差与本次实际资源采样的9.12e-8不是同一验证范围。

## 尚未关闭的问题

本批只添加对照验证，没有修改生产采样或求解算法，没有重跑接触矩阵。Flail场景接触结果仍1/3：120Hz通过，60Hz新增驱动不稳定，30Hz睡眠失败。静态目标旧矩阵仍9/12，不混用结果。

下一步需要真实UE同条件完整驱动轨迹，逐步对照动画时间、pelvis速度/刚度、实际关节目标及场景求解阶段，区分时序、输入精度与物理差异。不能据此次采样通过直接把问题归给某个solver模块。普通Ragdoll生命周期/Get-up/PoseRecovery、Mantle、完整Camera、十分钟性能等目标继续保留。主目录main，用户P4修改未动。
