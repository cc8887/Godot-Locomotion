## 具体差异与实现

捕获原实现 30 Hz 平台静止阶段第 293–295 帧的双臂形状姿态和原始几何尺寸，含没有相交的查询。
UE `Collisions::UpdateConstraint` 重新生成 capsule-box 流形，没有用 Godot 接触点驱动结果。
最初怀疑少了支撑点，实际六个前臂接触两端都是 2 点；差异是圆柱支撑点/端帽点的位置及顺序。
例如第 294 帧右前臂 Jolt 点间隙依次约 `-1.232550 / -1.015541 cm`，UE 约 `-1.015542 / -1.233011 cm`。
不能把观察结果描述为“已证实缺少接触点”。

`AlsCapsuleBoxManifold` 按原生规则区分 cylinder/end-cap：轴法向阈值 0.01、斜躺支撑阈值 0.707、重复点距离 0.1 倍半径；保存端点次序、圆柱法向和端帽点最后求解的次序。胶囊局部尺寸按原生 float 存储，公共平移和相对几何用 double。
仅在胶囊轴完全位于盒面外、完整半径范围位于该面内部时使用，额外避开 Godot 盒形 margin 的边缘范围。投影越过面边、深度穿透、边缘/角点仍交给旧几何查询，不用无限平面替代有限盒体。
查询支持两种身体顺序，返回原始有序身份对应的局部点和法向。零圆柱长度的胶囊保持原查询。

Core 接口支持显式 cull distance；原生对照包括 0 和 3 cm。实际查询仍使用原来的 0 cm 重叠发现契约，没有用扩大 margin 或静态地板尺寸估算原生身体的 cull distance。原生分离接触发现/持续流形仍是缺项。

## 原生与传输验证

`--trace-geometry` 扩展已有 `--trace-frames` / `--trace-bones`，只在启用时记录原始形状尺寸，包括返回零点的查询。`convex` 仅标识类型；本次 commandlet 明确只处理 capsule-box。

```text
Godot: res://scenes/tests/physics_core_joint_replay.tscn
--chains --drop --sleep --scene-world --platform=translate --hz=30
--trace-frames=293:295 --trace-bones=upperarm_l,lowerarm_l,upperarm_r,lowerarm_r --trace-geometry
--report=<新的绝对路径>

UE commandlet（完整 Editor target 构建/审计之后）:
-run=AlsGodotExport -PhysicsCapsuleGeometryInput=<采样日志绝对路径>
-PhysicsCapsuleGeometryOutput=<新的JSON绝对路径> -unattended -NullRHI
```

参考 `assets/config/v4_physics_capsule_geometry_reference.json`：336 条源查询中的 210 对 capsule-box，加 162 个独立合成姿态，两个 cull distance 共 744 项。
合成输入覆盖六面、水平/倾斜/垂直、0.009/0.011 和 0.706/0.708 阈值两侧、穿入/分离及大世界旋转。
其中 444 项满足 Core 明确支持区域（含 324 项合成输入），180 项有接触；0/1/2/3 点均覆盖。其余 300 项没有宣称由新算法覆盖。
有序局部点最大误差 `1.897731e-14 cm`，法向最大误差 0。

Godot 336 次实际形状/两端反序传输检查通过，最大点差 `9.536743e-7 cm`，法向差 `1.726467e-7`。三频率各 367 精度、6 几何、5 睡眠生命周期和 3 动态场景通过；最终补上零长度胶囊回退后，60 Hz 几何检查增至 7 并通过。
Core 新增 7 项边缘/深穿透回退、显式分离距离、margin 排除、非法维度/容量及零分配检查。
